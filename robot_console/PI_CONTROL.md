# 车载树莓派控制版

## 分工与当前交付状态

Windows 上位机只发送遥控意图并显示反馈；树莓派 ROS2 节点 `chassis_controller` 以 50 Hz 计算 yaw 纠偏及 A/B/C/D 目标速度；STM32 以 100 Hz 执行四轮速度 PI、读取编码器和板载 IMU，并保留欠压保护、协议校验及 300 ms 失联停车。

本次只完成本地源码、离线测试和 Windows 打包。未部署树莓派，未编译或烧录 STM32，未运行新版本实车测试。工程中已有 HEX 均不能代表此次修改。

这是一次需要配套更新的接口迁移：新固件标识为 `wheels-v2`，新软件遇到 `console-v1` 只监测和禁能，拒绝使能。旧上位机不支持新反馈标识。不要混用旧上位机或旧 HEX。

## 后续启用顺序

1. 用户自行从 `10.8/MDK-ARM/WHEELTEC.uvprojx` 编译新固件并使用 FlyMcu 烧录，恢复 BOOT0=0 后复位。
2. 使用本目录 `dist/RobotConsole.exe`。用户点击连接时，它才会通过 SSH 同步本版树莓派程序；本次任务未执行这一步。
3. 打开 `/dev/ttyAMA3`，收到 `wheels-v2` 反馈后允许使能。前后左右按钮仍按住运行、松手停止。
4. 初测使用 0.10 m/s。左转为 AB 后退、CD 前进；右转反向。直行起步锁定当前 yaw，用户已确认左转时 yaw 增大。

新上位机保留原雷达、地图和 IMU 显示功能。一个串口只能由一个控制节点持有；使用上位机时，它在网关进程中创建 ROS 控制节点。需要独立 ROS 控制时，应先断开上位机，再独立启动同一个节点，避免两个实例争用串口。

## 树莓派文件与参数

控制文件位于 `~/ros2_ws/robot_console/pi/`，容器内对应 `/workspace/ros2_ws/robot_console/pi/`：

- `chassis_node.py`：串口、ROS 速度输入、反馈发布、使能与超时。
- `heading_control.py`：yaw 外环及四轮速度分配。
- `chassis_params.yaml`：启动参数。上位机只在首次缺失时上传，后续连接保留树莓派的参数文件。

| 参数 | 初值 | 含义 |
| --- | --- | --- |
| kp | 0.010 | 航向比例，(rad/s)/deg |
| ki | 0.0 | 航向积分，(rad/s)/(deg*s)，初始关闭 |
| kd | 0.002 | 测量微分阻尼，(rad/s)/(deg/s) |
| max_wz | 0.08 | 最大纠偏角速度 rad/s |
| track | 0.130 | 有效轮距 m |
| yaw_enabled | true | 直线航向闭环开关 |

先禁能，再通过 ROS2 参数修改，例如在已加载 ROS 环境的容器终端执行：

```bash
ros2 param set /chassis_controller kp 0.015
```

运行时修改只作用于本次进程。要重启后保留，将相同值写入树莓派 `chassis_params.yaml`。不需要修改 STM32。yaw 误差与测量微分均处理 ±180° 跨界；前后换向重新锁定，倒车不反转纠偏符号；停止、主动转向、欠压和禁能清除历史。

## ROS 接口与独立运行

| 接口 | 类型 | 说明 |
| --- | --- | --- |
| `/cmd_vel` | `geometry_msgs/msg/TwistStamped` | `linear.x` 为前进 m/s，`angular.z` 为左转 rad/s；其他分量必须为零 |
| `/chassis/feedback` | `std_msgs/msg/String` | JSON：四轮目标/实测、yaw、电压、会话、确认序号和纠偏量 |
| `/chassis/enable` | `std_srvs/srv/SetBool` | 显式零速使能或禁能 |

特意使用带时间戳的 `TwistStamped`。有效期从原始时间戳算起为 200 ms，旧指令不能因网关重发而续命。生产者应使用树莓派当前 ROS 时间，以 20 Hz 或更高频率发送；使能前的速度不会保留，使能后 200 ms 内需收到新命令。普通 `Twist` 不能直接发布到此接口，后续接入导航时需匹配消息类型、时间戳并增加控制源仲裁。本版新增累计编码器与所选 IMU 航向的局部 /odom；尚未发布 TF 或集成 Nav2。

独立运行命令仅供后续用户执行，本次未部署或执行：

```bash
source /opt/ros/humble/setup.bash
python3 /workspace/ros2_ws/robot_console/pi/chassis_node.py --ros-args \
  --params-file /workspace/ros2_ws/robot_console/pi/chassis_params.yaml \
  -p auto_open:=true
```

运行环境沿用现有 `ros2-humble` 容器，需具备 rclpy、geometry_msgs、std_msgs、std_srvs、rcl_interfaces 和 pyserial。禁能服务示例：

```bash
ros2 service call /chassis/enable std_srvs/srv/SetBool '{data: false}'
```

新节点检测遥控、串口反馈或确认序号停滞超过 200 ms 时禁能；STM32 另有 300 ms 独立命令超时。Linux 卡顿、节点退出时不依赖上位机再次发送停止才能触发 MCU 超时。串口写失败时会尽力禁能并释放设备。当前尚未实测这些保护的停车距离。

## 累计编码器与里程计更新（2026-10-29）

MCU 每10ms唯一一次读取自由运行编码器计数器差值，同时用于轮速PI和四个uint32累计值。累计值按2^32模运算回绕，倒转递减；停车和禁能不清零，MCU复位归零。反馈0x82携带采样毫秒、当前会话、四轮累计值、能力位、故障位和舵机脉宽确认；与原0x81反馈成对发出，总计106字节，50Hz约5300字节/秒，低于115200/8N1带宽。

树莓派根据累计差和MCU采样时间计算轮子净位移，四轮平均距离与所选IMU的航向增量做平面运动积分，发布 nav_msgs/Odometry 到 `/odom`（odom→base_link），暂不发布TF。时间戳是ROS接收时刻，速度分母使用MCU采样间隔；并非硬件同步的传感器融合。四轮前进计数正方向沿用当前实测轮速约定。

计数和毫秒回绕用模运算处理；新会话、MCU时间回退、重复采样或超过1秒缺口重建基准，不把重启计数归零解释为位移。保留之前局部位置；断联期间的未知运动不能凭空恢复。计数异常对应超过3m/s时丢弃该次位移。中间少量漏帧仍能通过累计差保留距离。

参数 `wheel_diameter=0.048`（m）、`counts_per_rev=1040.0` 用于树莓派里程计换算，须实测校准。修改它们不会自动改变STM32速度PI内部的轮速换算。`/odom` 无法消除轮胎打滑和侧滑，协方差为未标定的保守初值，不能替代雷达/视觉定位。CSV完整JSON中保留原始无符号累计值；界面按32位有符号视图显示。

## IMU来源选择

`yaw_source=stm32` 默认使用现有板载yaw；`yaw_source=external` 使用 `/imu/data` 的 sensor_msgs/Imu 姿态。外部驱动需另行安装配置，本次没有部署USB IMU驱动。消息必须包含有效归一化四元数、有效姿态协方差和新鲜ROS时间戳；无姿态的 `/imu/data_raw` 不可直接作为yaw来源。

`external_imu_frame=base_link` 是要求的消息坐标系，驱动须已将安装方向转换成车体坐标系，左转yaw增大。仅改frame_id文字不能完成坐标变换。切换来源应先禁能；切换后重建航向和里程计基准。外接IMU过期200ms会使车轮禁能，不静默切换到板载IMU。STM32原有板载IMU就绪检查仍保留，外接来源不绕过这一硬件条件。

## C12H PA8舵机接口

H3：1=PA8信号、2=5V、3=AGND。新增 servo_output.c，由TIM1_CH1产生50Hz硬件PWM。上电脉宽0，即无高电平控制脉冲；失联或车轮禁能后持续保持最后有效脉宽，不自动回中。断电或MCU复位后恢复关闭，不恢复历史位置。

当前仅知道“众灵20kg数字舵机”，尚未确认具体PWM型号、供电要求和角度范围。因此 `servo_allowed=false`，默认禁止开启输出；固件通用硬边界500..2500μs不代表该舵机全部可用。树莓派初始限位为1000..2000μs，必须核对型号和机械限位后才设 `servo_allowed=true`。如实际是串口总线舵机，不能使用此PWM驱动。板载5V的输出能力仍需结合舵机负载确认。

上位机新增“前部舵机”：输入脉宽并点击“输出目标脉宽”；“关闭舵机输出”发送0。关闭按钮不受servo_allowed限制。状态显示的是定时器目标脉宽和指令确认序号，不是实际舵机角度；保持PWM也不保证机构在任意负载下不动。

ROS入口 `/servo/command` 为 std_msgs/String，JSON字段 `stamp_ns`（当前ROS时间纳秒）和 `pulse_us`（整数，0为关闭）。有效期200ms，一次命令一次确认，独立于车轮使能与租约。舵机命令绝不刷新STM32车轮300ms看门狗；通信失联期间只保持已有PWM。角度映射暂不写死，后续确认型号后在树莓派端实现。

`servo_min_us`、`servo_max_us`、`servo_allowed`、`yaw_source`、轮径与每圈计数均可禁能后通过ROS参数修改；永久设置写入树莓派chassis_params.yaml。

## 扩展故障状态

0x82故障位：bit0欠压，bit1曾发生串口接收错误（复位前保持），bit2车轮命令超时，bit3板载IMU未就绪。MCU欠压会撤销车轮使能并清除PI历史，电压恢复后必须重新零速使能；不会自动恢复旧运动。舵机仍按用户要求保持原脉宽。

此次修改前备份：`../output/actuator_feedback_20261029/before_changes.zip`。本次不部署、不编译或烧录STM32。19项离线测试不含真实ROS DDS与实车执行，不能当作硬件验收。

重新使能时等待新零速命令确认；MCU反馈撤销使能后不自动恢复非零运动。舵机保持策略不受车轮重新使能流程影响。


## 上位机yaw调参面板（2026-10-29）

在“IMU 姿态”页新增“直行航向调参”：Kp、Ki、Kd、纠偏限幅。连接后自动读取树莓派当前生效值；显示数据源选择与控制航向来源仍分开。

1. 先禁能小车，点击“读取当前参数”确认实际值。
2. 修改输入后点击“应用本次”，立即更新树莓派ROS控制节点。本次运行有效，重启后恢复配置文件值。
3. 确认参数合适后点击“应用并保存”，先应用，再将当前节点全部配置原子写入树莓派 `pi/chassis_params.yaml`，保留轮径、IMU来源、串口和舵机限位等生效值。重连上传不会覆盖该文件。

运行中和未读取参数时禁止应用。服务端会再次检查禁能状态与范围，越界或缺字段时整组拒绝，不部分修改。范围：Kp 0..0.2，Ki 0..0.02，Kd 0..0.05，纠偏限幅0..0.3 rad/s；这些是软件允许范围，并非建议一开始就用到上限。

保存使用JSON形式的有效YAML文档，重写后不保留原注释；保留本控制节点当前全部已支持配置值。如运行时已应用而写盘失败，界面明确显示“已应用但保存失败”，并回显实际生效值，旧文件不会被半写入内容覆盖。

该面板调整的是树莓派yaw外环，不修改STM32四轮速度PI参数，无需因此重新烧录STM32。本次只完成本地修改、5项调参测试、原19项控制测试、界面离线检查和Windows打包；没有部署树莓派。前期四轮执行、累计编码器和舵机接口仍需配套固件。
