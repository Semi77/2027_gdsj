# 树莓派部署说明

本文依据现有源码整理，描述已有环境的更新方式和新设备需要准备的内容；不是已经在新设备验证的一键安装方案。

## 环境约定

- 现有文档记录为树莓派 5、Debian 宿主机、Ubuntu 22.04 / ROS2 Humble 容器。
- 主容器名必须为 `ros2-humble`，上位机启动命令使用该名称。
- 宿主机登录用户的 `~/ros2_ws` 映射到容器 `/workspace/ros2_ws`。
- 上位机使用 SSH 密码登录及 sudo，当前要求两者使用同一个密码。
- 容器需要串口访问权限；底盘使用 `/dev/ttyAMA3`、115200/8N1。

## 文件布局

| 仓库内容 | 树莓派宿主机目标 |
| --- | --- |
| `robot_console/pi/` | `~/ros2_ws/robot_console/pi/` |
| `robot_console/shared/` | `~/ros2_ws/robot_console/shared/` |
| `ros2_lidar/delta2c_lidar/` | `~/ros2_ws/src/delta2c_lidar/` |
| `ros2_lidar/mapping/` | `~/ros2_ws/lidar_support/mapping/` |
| 实际场地地图 | `~/ros2_ws/maps/` |

地图定位导航当前固定读取容器中的 `/workspace/ros2_ws/maps/console_map.yaml`，必须连同 YAML 引用的地图图像一起提供。仓库的 `lidar_test` 是示例，不能直接当作实际场地地图使用。

## 已有树莓派更新

1. 首次使用时，在 Windows 终端运行 `ssh 用户名@树莓派地址`，核对并保存真实主机指纹。
2. 从本仓库重新打包上位机，或在安装依赖后从 `robot_console/main.py` 启动。
3. 点击“连接树莓派”。上位机通过 SFTP 更新主控相关的 `pi/` 和 `shared/` 文件，然后启动已有容器和 `gateway.py`。
4. `chassis_params.yaml` 仅在远端缺失时上传，已有文件不会覆盖。需要新增参数时，应核对设备配置并合并。
5. 连接后再打开底盘串口，确认 wheels-v2 反馈，再启动所需雷达、建图或导航功能。

自动同步不安装 ROS2，不创建 Docker 容器，也不部署雷达包、建图目录、地图或独立舵机节点。EXE 同步的是打包时附带的源码，修改 Python 后需要重新打包。

## 新设备初始化

当前仓库没有 Dockerfile、Compose 配置或完整环境安装脚本。新设备需要先配置 Docker、上述目录映射、串口、网络和 ROS2 Humble 环境，再执行应用部署。

主容器需要 rclpy、pyserial、PyYAML 和相关 ROS 消息、服务、TF 包；建图需要 Cartographer ROS；导航需要 Nav2、nav2_bringup、nav2_simple_commander 和 AMCL。具体依赖还应结合包声明与运行检查核对。

按文件布局复制雷达包后，在容器内执行：

```bash
source /opt/ros/humble/setup.bash
cd /workspace/ros2_ws
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install --packages-select delta2c_lidar
source install/setup.bash
```

复制建图目录和实际地图，再通过上位机连接部署主控。`robot_console/pi/` 与 `shared/` 直接由 Python 运行，不需要 colcon 构建。

## 独立运行底盘节点

先断开上位机，避免多个节点争用串口。在容器中运行：

```bash
source /opt/ros/humble/setup.bash
python3 /workspace/ros2_ws/robot_console/pi/chassis_node.py --ros-args \
  --params-file /workspace/ros2_ws/robot_console/pi/chassis_params.yaml \
  -p auto_open:=true
```

打开串口不等于使能车轮。接口和参数操作见 `robot_console/PI_CONTROL.md`。

## 舵机与接线核对

舵机角度节点位于 `ros2_servo/servo_pwm_controller/`，同时需要旁边的 `fastdds_udp.xml`。原机使用独立 `ros2-servo` 容器；现有脚本依赖该容器和 `/home/xu` 路径，新机器需要调整。仓库未包含原容器的完整创建配置。

角度节点经 `/servo/command` 调用底盘节点，再通过 UART3 控制 STM32 PA8。仓库主控参数默认 `servo_allowed: false`，范围为 1000–2000 μs；原机舵机文档记录的参数是已解锁、500–2500 μs，迁移时需按实际舵机和机械限位核对。

早期雷达 README 与后续接线记录存在 GPIO、串口差异，必须按实际接线确认雷达设备名。底盘 UART3 为树莓派 GPIO8/TX → STM32 PC11/RX、GPIO9/RX ← PC10/TX，并共地。

## 部署后核对

依次确认底盘固件标识、四轮与 IMU 反馈、雷达 `/scan`、里程计 `/odom`、地图和坐标链。导航操作见 `robot_console/NAVIGATION.md`。当前源码上传不代表新设备完成运行或实车验收。
